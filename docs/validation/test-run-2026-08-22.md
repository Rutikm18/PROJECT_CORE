## Findings

### AL-1 — Admin password served unauthenticated on every default deployment  (CRITICAL)

`GET /api/v1/auth/policy` requires no credentials and returns:

```json
"default_credentials": {"active": true, "email": "admin@attacklens.ai",
                        "password": "!HLwS=f73fHo$?p!#M77XA*M"}
```

The password is hardcoded at `manager/manager/api/auth_ui.py:108`, so it is byte-identical
on every install. The suppression gate at `auth_ui.py:128` works correctly — verified
empirically: with `DASHBOARD_PASSWORD_HASH` set, the endpoint returns
`{"active": false, "email": null, "password": null}`.

The problem is that nothing in the shipping deployment path sets it:

- `docker-compose.yml` does not pass `DASHBOARD_PASSWORD_HASH`, `DASHBOARD_PASSWORD`, or
  `DASHBOARD_EMAIL` into the manager container at all.
- `.env.example` never mentions any of them — no operator guidance exists.
- `caddy` publishes the manager on `:80` and `${BIND_PORT:-8443}`, with Let's Encrypt when
  `DOMAIN` is set.

So a stock `make up` publishes its admin credentials to the internet at a well-known path,
and an operator following the documented setup has no supported way to prevent it without
editing `docker-compose.yml`. The in-code warning ("Set DASHBOARD_PASSWORD_HASH before
deploying") is correct advice that the deployment cannot actually act on.

**Fix:** plumb `DASHBOARD_PASSWORD_HASH` / `DASHBOARD_EMAIL` through the compose manager
service, document them in `.env.example`, have `env.sh` generate a hash alongside
`ADMIN_TOKEN`/`JWT_SECRET`, and consider gating `default_credentials` on a loopback/private
source address in addition to the `active` flag.

### AL-2 — mypy in `make lint` has never checked anything  (HIGH)

`make lint` runs mypy, which exits 2 (fatal) before analysing a single project file:

- `pyproject.toml` pins `python_version = "3.11"`; numpy's bundled stubs use `type`
  statements requiring 3.12+ → fatal `[syntax]` error kills the run.
- `warn_unused_imports` is not a valid mypy option — that config line is a no-op.

With `--python-version 3.13`, mypy runs and reports **465 errors**. 182 of them are one root
cause: an unannotated DB connection attribute in `manager/manager/indexer.py` inferred as
`None`, cascading through every `.execute()`/`.commit()` call. The `[union-attr]` cluster in
`detections/developer_security.py` (lines 233, 240, 463-483) is a genuine unguarded-`None`
risk worth reviewing.

**Fix:** bump `python_version`, drop the bogus option, annotate `indexer._conn`.

### AL-3 — Agent integration tests write into the shared `manager` database  (HIGH)

`agent/tests/integration/test_enrollment_flow.py` sets `DATA_DIR` to a `tmp_path_factory`
directory, which was the SQLite-era isolation mechanism. Under Postgres, `DATA_DIR` only
controls `TelemetryStore` (a file archive) — the database comes from `DATABASE_URL`,
defaulting to `postgresql://attacklens:attacklens@localhost:5432/manager`.

Verified: this run inserted 7 `integ-agent-00N` rows into the shared `manager` DB alongside
the real agent `mac-e33b9d33-…`. Test outcomes can therefore depend on accumulated state,
and repeated runs pollute a developer's working database.

`manager/tests/conftest.py` already has the correct pattern (`pg_manager_dsn` — CREATE/DROP
per test, try/finally). The agent integration fixture should use it.

### AL-4 — `templates/index.html` is a stale fallback that would serve a blank dashboard  (MEDIUM)

`server.py:887` resolves the SPA entry as `static/index.html` first, then
`templates/index.html`. `static/index.html` is coherent (all 4 referenced assets present,
all served 200 — verified live). `templates/index.html` references three assets that do not
exist on disk: `index-C-ffOH8Q.css`, `index-ah1acFF2.js`, `vendor-EH7tLb-9.js`.

Not currently user-visible, but the fallback exists for packaging variants that ship without
`static/`, and in that case it renders blank. `make build-dashboard` does the `cp` that
resyncs it; whoever last built ran `npm run build` directly and skipped it.

### AL-5 — CI cannot pass as written  (HIGH, previously reported)

Re-confirmed by execution: `ci.yml` runs `pytest tests/integration/`, a directory that does
not exist (pytest exits 4). It never runs `agent/tests/` or `manager/tests/` — 1,390 of the
1,540 tests. It has no Postgres service, so the 12 `pg_manager_dsn` files could not run there
anyway. Lint and bandit steps also exit non-zero (above). Frontend tests are absent entirely.

### AL-6 — Trojan Source false positive is permanent  (LOW)

bandit's only HIGH finding: `detections/scheduled_task.py:76` contains a literal
`​-‏` range inside `_HOMOGLYPH_RE` — the regex that detects hidden-character
attacks. Legitimate, but writing it as escape sequences (`r"[​-‏]"`, which `re`
interprets identically) keeps the behaviour and stops tripping every scanner forever.

### AL-7 — Orphaned test databases  (LOW)

6 `test_*` databases dated 2026-06-23/24 remain in the Postgres volume from earlier
interrupted runs. The manager fixture's try/finally cannot fire when a run is killed. A
`DROP DATABASE` sweep for `test_%` at session start would keep the instance clean.
