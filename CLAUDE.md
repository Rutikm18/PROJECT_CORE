# Learnings log

Whenever a new concept, library, pattern, or design decision is actually implemented in this project during a session (not just discussed or rejected), append it to `LEARNINGS.md` at the project root before the session ends — do this proactively, without waiting for `/learnings` to be invoked.

Follow the exact format and rules already defined in `.claude/commands/learnings.md`: short **What**/**Why** entries, grouped under a `## <date>` heading, skip anything already documented, append-only, no rewriting existing entries.

`/learnings` still exists as a manual fallback (e.g. to force a check mid-session), but it should not be the only trigger.
