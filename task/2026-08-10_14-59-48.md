## Step-by-step approach

### Phase 0 — Quick wins

**T0.1 Global refresh button (top bar)**
- Add `RefreshContext` exposing `refreshNonce` + `triggerRefresh()` + in-flight count.
- Hooks include `refreshNonce` in deps → single click re-fetches all pages.
- Button in `TopHeader` right zone (next to clock); spinner while in-flight.

**T0.2 Detection-rule verification harness**
- Enumerate every rule: YAML packs + code detections.
- Feed representative fixtures per section; assert each rule fires without error.
- Emit coverage report: fired / never-fires / errored per rule id.

### Phase 1 — Custom rules in detection pipeline

**T1.1** Add `layer: "raw" | "correlation"` to custom-rule schema, API, UI form.
**T1.2** Wire raw-layer evaluator into `engine.py` per-payload pass; correlation stays in `custom_correlator`.
**T1.3** On/off toggle surfaced in UI (existing `/toggle` endpoint).
**T1.4** External YAML ingest + pull-all reload endpoint.
**T1.5** Tests for raw-layer eval, toggle, YAML ingest.

### Phase 2 — OpenRouter + Codex + model choice

**T2.1** OpenRouter provider (thin OpenAI-compatible, `base_url=https://openrouter.ai/api/v1`).
**T2.2** Free models + Codex registered in `PROVIDER_MODELS`.
**T2.3** Model-choice UI/API per task (validation vs remediation) with health-check.
**T2.4** Provider tests (mocked HTTP), settings round-trip.

### Phase 3 — Validation deepening

**T3.1** Fallback chain — 429/503 → next configured model.
**T3.2** JSON parse hardening + safe defaults.
**T3.3** Verdict explainability record (which factor drove verdict).
**T3.4** Gap list + fixes from full `ai_validator.py` audit.
**T3.5** Error handling + tests.

### Phase 4 — Architecture review

**T4.1** Written pass: detection→validation data flow, rule scoping, threat surface. Record in `LEARNINGS.md`.
